# Travel Planner PWA

A mobile-first, offline-first personal travel planning PWA. The project is intentionally generic: it is designed to support any future trip rather than encode one destination or itinerary.

## Current milestone

**Milestone 2 — Local Data Foundation (`v0.2`)**

Implemented:

- React + TypeScript + Vite application shell
- Hash-based routing for GitHub Pages
- Responsive phone/iPad navigation
- Installable PWA with offline app-shell caching
- IndexedDB persistence through Dexie
- Dexie React live-query integration
- Typed v1 data schema with 18 tables
- UUIDs, timestamps, revisions, and soft-delete utilities
- Repository/service boundary for database access
- Persistent-storage request with graceful browser fallback
- In-app database diagnostics and persistence test data
- Deterministic dependency lockfile generated by the Milestone 2 bootstrap workflow
- GitHub Pages CI/CD

Not implemented yet:

- Trip creation and management (Milestone 3)
- Day-by-day itinerary CRUD (Milestone 4)
- Places, transport, bookings, packing, Today Mode, backup/export, and later smart planning

## GitHub Pages

The included `.github/workflows/deploy-pages.yml` builds and deploys on every push to `main`. It uses the committed lockfile with `npm ci` and automatically sets Vite's base path from the repository name.

Repository setup:

1. Open the repository on GitHub.
2. Go to **Settings → Pages**.
3. Set **Source** to **GitHub Actions**.
4. Push to `main` or run the deployment workflow manually.

A repository named `travel-planner` is deployed correctly under `/travel-planner/`.

## Routing

The project uses `HashRouter`, giving routes such as:

```text
/#/trips
/#/trip/:tripId
/#/trip/:tripId/itinerary
/#/trip/:tripId/today
/#/trip/:tripId/more
```

This avoids deep-link refresh problems on static GitHub Pages hosting.

## Local data architecture

Milestone 2 introduces `TravelPlannerDB` (IndexedDB via Dexie) with tables for:

- travel profiles and trip preferences
- trips, travelers, destinations, and trip days
- places and trip-specific saved places
- activities and local transport segments
- major travel legs and stays
- bookings
- packing lists, categories, and items
- flexible trip-information sections and items

Core records use UUIDs plus `created_at`, `updated_at`, `deleted_at`, and `revision`. Important records are designed for soft deletion so later backup, undo, and synchronization features can be layered on safely.

The **Local database** panel on My Trips is intentionally temporary validation UI for Milestone 2. Add the Lisbon test data, fully close/reopen the PWA, confirm the record count remains, and then clear the sample.
